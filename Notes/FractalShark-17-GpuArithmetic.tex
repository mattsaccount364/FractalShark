\section{GPU Reference-Orbit Implementation}
\label{subsec:ref-orbit-gpu}

Deep Mandelbrot views require a high-precision reference orbit before the
perturbation renderer can evaluate nearby pixels.  The production GPU backend
implements the complete recurrence
\begin{align}
  x_{n+1} &= x_n^2-y_n^2+c_x, \\
  y_{n+1} &= 2x_ny_n+c_y
\end{align}
inside one persistent cooperative CUDA kernel.  High-precision addition,
transforms, pointwise products, carry propagation, normalization, derivative
updates, periodicity checks, and bounded orbit publication are phases of that
single engine rather than independently selectable arithmetic operators.

\subsection{Architecture and Execution Context}
\label{subsec:ref-orbit-architecture}

The host selects a storage bucket from the generated
\code{GenericSharkFloatParams} families and then restricts the active precision
to the requested limb window.  \code{ReferencePreparedTables} owns the device
workspace, root tables, and twiddle tables for that precision.  Setup executes
once, while \code{GpuOrbitSession} owns the result descriptor and advances the
orbit through repeated \code{InvokeChunk} calls.  Each chunk publishes at most
\code{MaxOutputIters} entries, which bounds transfer size without introducing a
kernel launch for every recurrence.

The generated CUDA translation units instantiate four families:
\code{HpSharkFloat\_Conversions}, \code{HpSharkReference},
\code{ReferenceGpuLoop}, and \code{SharkNTT\_Primitives}.  The first family
performs host/device representation conversion.  The remaining families
provide the reference lifecycle, persistent kernel, and reusable Montgomery
primitives required by the kernel and its CPU oracle.

\subsection{High-Precision Floating-Point Representation}
\label{subsec:hpfloat-model}

An \code{HpSharkFloat} value consists of a sign, a base-$2^{32}$ significand,
and an exponent.  If the significand limbs encode the nonnegative integer $M$
and the sign bit encodes $s\in\{-1,1\}$, the represented value is
\begin{equation}
  v=sM2^e.
  \label{eq:hp-shark-value}
\end{equation}
The storage bucket fixes the limb capacity, while the effective precision may
use a suffix of that capacity.  Normalization retains the most significant
requested limbs and adjusts $e$ so that truncation does not change the value's
scale.

The recurrence aligns terms in the coefficient domain.  A shared exponent is
chosen for every output stream, and each term records the nonnegative shift
needed to reach that exponent.  Zero terms do not constrain the shared
exponent.  The planner selects the smallest supported power-of-two transform
that contains the shifted linear-convolution support.

\subsection{High-Precision Addition in the Fused Kernel}
\label{sec:hp-add}

Addition and subtraction appear after the inverse transform as signed
base-$2^{32}$ streams.  The kernel does not materialize normalized products and
then invoke a separate addition operation.  Instead, spectral contributions
for $x^2$, $-y^2$, $c_x$, $2xy$, and $c_y$ accumulate directly into the real
and imaginary output spectra.  Inverse transformation produces signed limbs
for the complete real and imaginary recurrence outputs.

Signed carry propagation is a dependency-light-block problem.  Each thread
summarizes a fixed limb interval as a compact transfer function.  A packed
prefix scan composes the summaries, distributes the incoming carry state, and
allows each interval to emit final limbs independently.  Magnitude extraction
and normalization follow the scan.  The derivative streams use the same
mechanism when Newton--Raphson support is enabled.

\subsection{Number-Theoretic Transforms in the Reference Engine}
\label{sec:ntt-multiply}

The reference engine splits every 32-bit limb into base-$2^{16}$ coefficients.
For an effective precision of $n_{32}$ limbs, the base plan contains
\begin{equation}
  L=2n_{32}
\end{equation}
input coefficients.  A product contains at most $2L-1$ coefficients before
alignment shifts are applied.  \code{ReferenceNTT} therefore combines the
coefficient support with the largest requested shift and rounds the result to
a supported power-of-two transform length $N$.

Transforms use the prime
\begin{equation}
  p=2^{64}-2^{32}+1,
\end{equation}
which supplies power-of-two roots of unity for every supported stage.  Setup
generates forward and inverse stage roots and twiddle tables once per active
plan.  Montgomery multiplication performs modular products without integer
division.  The checked-in \code{SharkNTT\_Primitives} instantiations provide the
same operations to the kernel and the host-side correctness model.

Forward transforms use decimation in frequency and retain bit-reversed spectra.
Pointwise products and aligned linear terms remain in that order.  Inverse
decimation in time consumes the bit-reversed spectra and returns natural-order
coefficients, avoiding explicit permutation buffers in the hot path.

\subsection{Fused NTT Reference Step}
\label{subsec:fused-ntt-reference-step}

Let $X$, $Y$, $C_x$, and $C_y$ denote aligned coefficient polynomials.  The
kernel forms
\begin{align}
  R &= X\star X-Y\star Y+C_x,
       \label{eq:fused-reference-real} \\
  I &= 2(X\star Y)+C_y,
       \label{eq:fused-reference-imag}
\end{align}
where $\star$ denotes linear convolution.  After transformation, the same
calculation is pointwise:
\begin{align}
  \widehat R_k &= \widehat X_k^2-\widehat Y_k^2+\widehat C_{x,k}, \\
  \widehat I_k &= 2\widehat X_k\widehat Y_k+\widehat C_{y,k}.
\end{align}
The constants enter as aligned linear spectra; they are not promoted to
standalone normalized high-precision values during the iteration.

\subsubsection{Operation Schedule}
\label{subsec:fused-ntt-operation-schedule}

One nonzero iteration proceeds through the following cooperative phases:
\begin{enumerate}
  \item A leader thread builds and publishes the iteration plan.
  \item Threads pack aligned orbit and derivative coefficients.
  \item Forward NTT stages transform the active streams.
  \item Pointwise evaluation accumulates the real, imaginary, and optional
        derivative spectra.
  \item Inverse NTT stages recover signed coefficient streams.
  \item Packed prefix scans propagate carries and borrows.
  \item Normalization publishes the next orbit state and optional derivatives.
  \item Periodicity and escape logic publish a bounded batch of orbit entries.
\end{enumerate}
Grid-wide synchronization occurs only at data-dependency boundaries shared by
all streams.  The same workspace is reused across iterations and chunk
invocations.

\subsubsection{Carry and Exactness Bounds}
\label{subsec:fused-ntt-carry}

Centered residues are interpreted as signed coefficients before carry
propagation.  The planner requires the absolute coefficient sum, including all
aligned product and linear terms, to remain below $p/2$.  Under that condition,
conversion from the residue field recovers the unique signed integer
coefficient.  The base-$2^{16}$ packing plan and supported transform limits
provide the required headroom for the orbit and derivative schedules.

\label{subsec:fused-ntt-range}
The final base-$2^{32}$ carry remains sequential in the mathematical sense, but
the packed transfer-function scan evaluates it in logarithmic parallel depth.
No coefficient may wrap around the cyclic transform boundary; $N$ is therefore
chosen from the complete shifted support rather than from the unshifted product
length alone.

\subsection{Periodicity and Newton--Raphson Derivatives}
\label{subsec:fused-ntt-periodicity}

The ordinary reference-orbit path publishes iteration values and checks escape
and periodicity state inside the persistent loop.  The Newton--Raphson family
also advances
\begin{align}
  d_{n+1} &= 2z_nd_n+1, \\
  q_{n+1} &= 2(d_n^2+z_nq_n),
\end{align}
where $d_n=\partial z_n/\partial c$ and
$q_n=\partial^2 z_n/\partial c^2$.  The high-precision derivative $d_n$ uses
the same fused transform and carry pipeline as the orbit.  The second
derivative uses the configured HDR type after each completed recurrence.

Checkpoint resume preserves the distinction between fresh initialization and
continuation: \code{startIter}=0 initializes the recurrence, while a positive
value consumes the supplied orbit and derivative state.  Progress and abort
callbacks are evaluated at bounded intervals without changing that contract.

\subsection{Synchronization Amortization}
\label{subsec:amortize-sync}

Large transforms require grid synchronization between stages, but a persistent
kernel amortizes launch overhead and keeps the complete recurrence resident.
The kernel advances every enabled stream through a common stage schedule, which
also permits forward and inverse stages to share barriers.  Prepared root and
twiddle tables eliminate per-iteration allocation and table construction.

\subsection{Checksum-Guided Host--Device Validation}
\label{sec:checksums}

Debug builds can record checksums at packing, transform, pointwise, carry, and
normalization boundaries.  The retained \code{ReferenceReferenceOrbit2} CPU
oracle executes the same plan and records the corresponding host states.
\code{ChecksumsCheck} compares those states by purpose and call index, which
localizes a disagreement to a pipeline boundary without retaining obsolete
arithmetic test operators.

\subsection{Application and Test Integration}

The application exposes one production selector.  The portable menu labels it
\emph{GPU-Accelerated Reference Orbit}, the Feature Finder labels its backend
\emph{NR Inner Loop: GPU}, and the CLI accepts \code{GPU}.  Both application
paths dispatch through \code{GpuOrbitSession} and
\code{EvaluateCriticalOrbitAndDerivs\_GPU}.

The CUDA test harness retains \code{Operator::ReferenceOrbit2} as its sole
operator entry to preserve the established correctness-test identity.  The
production lifecycle and file names are unnumbered: setup uses
\code{PrepareHpSharkReferenceTables}, execution uses
\code{InvokeHpSharkReferenceKernel}, and shutdown uses
\code{ShutdownHpSharkReferenceKernel}.  Generic orbit save, load, comparison,
and MPIR validation remain independent of the GPU implementation name.
