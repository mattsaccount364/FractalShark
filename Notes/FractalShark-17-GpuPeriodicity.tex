\section{Per-Iteration Periodicity Checking under High-Precision Arithmetic on the GPU}
\label{sec:hp-periodicity}

The \FractalShark{} fused v2 GPU reference-orbit implementation
(\cref{subsec:ref-orbit-gpu}) evaluates the Mandelbrot recurrence
\(
z_{n+1} = z_n^2 + c
\)
using high-precision arithmetic for the state \(z_n\), while interleaving a
reduced-precision periodicity/termination test before the high-precision
recurrence stages.  Early termination can avoid later arithmetic, but the
check and its required cooperative-grid synchronization have a measurable cost
that depends on precision and launch configuration.

The CUDA engine can be selected explicitly or through the compatible-format
\code{Auto} policy in \cref{subsec:ref-orbit-pipeline}. Its stored-output type \code{T} may be
\code{HDRFloat<float>}, \code{HDRFloat<double>}, or
\code{HDRFloat<CudaDblflt<dblflt>>}.  The CUDA path forces
\code{PExtras::Disable} and \code{ReuseMode::DontSaveForReuse}; neither produces
a compressed or intermediate-reuse orbit.  These are policy constraints of the
CUDA application path.

\paragraph{State extraction and logging.}

At iteration \(n\), the high-precision state \((x_n, y_n)\) is available in the
persistent kernel's reference state. The active fused checker,
\code{ReferenceDetail::CheckPeriodicity}, converts
these values into a reduced high-dynamic-range scalar format,
\(\mathrm{HDR}(\cdot)\), via a lossy extraction
(\code{ToNormalized\allowbreak HDRFloat}) and stores the resulting pair in a per-iteration output
buffer:

\begin{equation}
  \widehat{x}_n \leftarrow \mathrm{HDR}(x_n), \quad
  \widehat{y}_n \leftarrow \mathrm{HDR}(y_n), \quad
  \code{OutputIters}[k] \leftarrow (\widehat{x}_n, \widehat{y}_n).
  \label{eq:hdr-extraction}
\end{equation}

Here $k$ is the iteration index within the current GPU invocation, while $n$
is the mathematical orbit index. Ordinary generation starts at $z_1=c$ and
$d_1=1$; the host supplies the preceding zero entry. The output buffer contains
the reduced reference samples consumed downstream, as well as supporting
diagnostics. A later invocation reuses the persistent state with $k$ reset
to zero; it does not restart the mathematical orbit or derivative.

\paragraph{Derivative-based periodicity criterion.}

The CPU and active GPU checkers use the same derivative recurrence
\eqref{eq:dzdc-def}, the same componentwise norms
\eqref{eq:periodicity-norms}, and the same strict near-return condition:

\begin{equation}
  \max(|\widehat{x}_n|,|\widehat{y}_n|)
  <2R\max(|\hat d_{x,n}|,|\hat d_{y,n}|).
  \label{eq:periodicity-ineq}
\end{equation}

The shared screen-geometry derivation and factor-two bound are in
\cref{subsec:ref-orbit-view-bounds,subsec:ref-orbit-linear-radius}; their
nonlinear and reduced-precision limits are in
\cref{subsec:ref-orbit-near-return-limits}. The host passes the same stored
vertical half-height through \code{GetMaxRadius()} into \code{RadiusY}.
The GPU therefore retains the same aspect-ratio and reference-offset
qualification as the CPU test.

The orbit components use \code{HpSharkFloat}; the checker's \code{DzdcX},
\code{DzdcY}, and \code{RadiusY} use
\code{SharkFloatParams::Float}, an HDR type with the selected float, double,
or double-float significand. These reduced derivative fields are separate
from the high-precision derivative streams used for Newton--Raphson work.
If the comparison fails, the checker advances both derivative components
using the unchanged old pair, then applies the escape test. If it succeeds,
it sets \code{PeriodicityStatus} to \code{PeriodFound}, counts the current
sample, and returns before advancing the high-precision recurrence.
The status is the implementation's near-return result, not an exact-period
certificate.

\paragraph{Threshold normalization.}
HDR multiplication can leave a significand outside its normalized interval.
The checker calls \code{HdrReduce} on the completed $2Rr_0$ product before
the reduced comparison, which orders exponents before significands.
For $c=3/8$ and $R=3/16$, the first check is equality and continues. At
$z_2=33/64$, the derivative is $d_2=7/4$ and the threshold is $21/32$.
The unnormalized threshold can be stored as $(21/8)2^{-2}$, whereas its
normalized representation is $(21/16)2^{-1}$. Comparing the former by
exponent first would miss $33/64<21/32$. The example is exact in all three
supported significand families, so the required normalization is independent
of their rounding accuracy. Regression cases check this result within one
invocation and across a chunk boundary, together with strict equality cases.

\paragraph{A numerical interpretation.}
For $c=-0.999$, the first two orbit values are $z_1=-0.999$ and
$z_2=-0.000999$, with $d_2=2c+1=-0.998$.  Taking $R=0.001$ gives
$|z_2|=0.000999<2R|d_2|=0.001996$, so the heuristic fires even though
$z_2\ne0$.  At the nearby exact period-two center $c=-1$, the return
is zero.  The example explains why the test is useful for early termination
and why its positive result is not an exact periodicity certificate.

\paragraph{Escape test.}
The checker also applies a reference-generation bailout in the same reduced
domain.  It forms the cheap proxies
\(
\widehat{x}_n + \widehat{c}_x
\)
and
\(
\widehat{y}_n + \widehat{c}_y
\),
the checker evaluates
\begin{equation}
  \lVert\widehat{z}_n + \widehat{c}\rVert_2^2
  = (\widehat{x}_n + \widehat{c}_x)^2 + (\widehat{y}_n + \widehat{c}_y)^2,
  \label{eq:gpu-escape-norm}
\end{equation}
and declares \code{Escaped} when this value exceeds a fixed threshold
(\code{256.0} in the current implementation). As with the periodicity
criterion, the test uses HDR arithmetic to avoid high-precision control-flow
costs on the device. The expression
$\widehat z_n+\widehat c$ is not $\widehat{z_{n+1}}$; for $z_n=2$ and
$c=1$, the former is $3$ and the latter is $5$.  The threshold and proxy
match the application reference contract, rather than the usual direct-pixel
$|z_n|>2$ test.

\paragraph{Control-flow placement and synchronization.}
Periodicity checking is invoked once per iteration at the top of the reference
step, before the fused high-precision stages compute
\(z_{n+1}\). In the production kernel, a single distinguished thread
(\code{block 0, thread 0}) executes the checker and updates the shared
termination flag stored in the global \code{reference} structure. The kernel
then executes a cooperative-grid barrier:
\begin{equation}
  \code{grid.sync()},
  \label{eq:grid-sync}
\end{equation}
ensuring that (i) all blocks observe a consistent \code{PeriodicityStatus} and
(ii) any updates to \code{DzdcX}, \code{DzdcY}, and the output buffer are
visible before subsequent work proceeds. If termination is requested, the
iteration loop exits immediately; otherwise, the kernel proceeds into the
fused NTT recurrence that produces the next high-precision state.

The organization isolates termination logic from the fused recurrence pipeline
while maintaining grid-wide early-exit behavior.  The checker publishes its
status through one explicit \code{grid.sync()} per iteration.  The recurrence uses the same publication
boundary to expose the iteration plan built by the leader.  The synchronization
cost is amortized by the subsequent high-precision work but is not assumed to be
negligible. A completed recurrence or a terminating sampled check increments
\code{OutputIterCount}; a stop at local index $k$ therefore reports $k+1$
samples for that invocation. Chunk entry resets this count and the running
status while preserving the orbit and derivative. The host accumulates chunk
counts and translates \code{PeriodFound} into the stored maybe-periodic
metadata. \Cref{subsec:fused-ntt-periodicity} describes the fused loop's
publication and resume semantics.

\paragraph{Alternative host-side periodicity checking.}
An alternative design would be to retain the authoritative high-precision orbit
state entirely on the device, periodically copy the full-precision values
\((x_n, y_n, dz_n/dc)\) back to the host, and perform periodicity and escape
testing on the CPU using existing MPIR-based logic. While conceptually simpler,
this approach is impractical at large precisions: each iteration would require
transferring hundreds to thousands of limbs per component over the PCIe bus,
and the cumulative bandwidth and synchronization costs would dominate the total
runtime. Moreover, host-side checking would introduce additional latency and
force a tighter coupling between device execution and CPU control flow. By
performing periodicity detection directly on the GPU using reduced HDR
representations, the implementation avoids repeated large data transfers while
preserving an early-termination mechanism integrated with the
cooperative-grid execution model.  The cost remains one reduced check and its
publication barrier per iteration; the gain depends on how much later
high-precision work termination avoids.

The reference-orbit algorithms described above rely on high-precision arithmetic
that must execute efficiently on the GPU.  The next chapter details the
NTT-based arithmetic engine that provides this capability.
